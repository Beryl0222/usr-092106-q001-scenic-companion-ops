# 景区伴游任务中枢

面向景区数字运营中心的伴游任务后端：把游客同行组、无障碍需求、分时入园、设备能力、讲解内容版本、实时路段容量与现场告警编排成可调整的游程，并对每一次调度保持可追溯。

## 已有内容

- `contracts/domain.schema.json`：领域事件的基础字段、聚合类型和事件名称。
- `data/sample.json`：可用于联调的中文样例记录。
- `src/`：事件存储与全部业务流程（见下）。
- `tests/`：契约校验 + 各模块单测 + 端到端调度场景。

## 模块结构

| 模块 | 职责 |
| --- | --- |
| `src/event-store.js` | 追加式事件存储：信封校验、聚合版本从 1 递增、写入即冻结 |
| `src/consent.js` | 录像/照片/游记生成分别明示授权；默认拒绝，设备默认设置不构成授权 |
| `src/media.js` | 媒体处理流水线：撤回授权即丢弃待处理任务，后续处理被闸门拦下 |
| `src/telemetry.js` | 断网重连后的定位/电量消息去重（message_id + device_seq）与乱序重整 |
| `src/fleet.js` | 机器人/外骨骼/人工讲解队统一建模，按无障碍需求与讲解内容版本匹配 |
| `src/routing.js` | 路网、实时路况（施工/暴雨/容量）与带拥堵成本、改线惩罚的规划器 |
| `src/incidents.js` | 施工、暴雨、拥堵、设备故障、紧急疏散的分级告警生命周期 |
| `src/dispatcher.js` | 调度中枢：改线、疏散抢占、故障转交、游客视图与值班回放 |
| `src/ops.js` | 组合根：装配以上模块，`createCompanionOps({ network, now })` 即可运行 |

## 关键行为

- **改线说明原因**：每次 `ROUTE_REVISED` 携带 `reason`（施工封闭/暴雨预警/突发拥堵/电量不足/人工干预/紧急疏散等）与 `decision_id`。
- **防反复导向**：队伍被迫离开的路段进入冷却期（默认 20 分钟）并施加改线惩罚，冷却期内不会把同一队伍导回刚避开的拥堵点；当前正在经过的路段不算"重回"。
- **紧急疏散压过普通推荐**：疏散中的队伍只接受 `emergency` 优先级的改线，普通推荐被抑制，解除后自动恢复游程。
- **设备故障无缝转交**：故障即释放并优选同类型设备、兜底人工讲解队，交接以 `supersedes` 串联，游程不中断；无接替资源时告警升级为紧急。
- **授权与审计**：撤回授权后停止后续处理（待处理任务丢弃、新处理被拦截），安全审计日志只追加不删除。
- **游客视图**：`dispatch.visitorView(partyId)` 返回当前路线、设备交接时间线、各版本等待变化与实时预计等待。
- **值班回放**：`dispatch.replayDecision(decisionId)` 返回该次调度使用的客流、预警、施工与人工干预快照；`replayRoutePlan(routePlanId)` 回放整条游程的决策链。

## 领域边界

事件一旦被接收，其标识、发生时间和版本不应被原地改写；业务更正（改线、交接、告警升级、授权撤回）一律产生后继记录。涉及个人、机构或商业敏感信息时，调用方只读取完成职责所必需的字段。
